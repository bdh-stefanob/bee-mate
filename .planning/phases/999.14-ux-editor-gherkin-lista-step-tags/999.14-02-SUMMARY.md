# Phase 999.14 Plan 02: UX Editor Gherkin — colonne sticky + Step compatti Summary

Editor Gherkin riorganizzato: colonna Steps sticky (sempre visibile mentre l'editor scorre con la pagina), pannello Step compatto di default con ricerca/filtri sempre accessibili, box "Preview .feature" rimosso.

## Cosa è stato fatto

### Task 1 — Colonne a scroll/sticky + rimozione Preview (`fbd9b07`)
File: `web-ui/src/app/editor/_content.tsx`

- Ristrutturato il contenitore "Scrollable content" da `flex-1 overflow-y-auto` (singolo wrapper che faceva scorrere via entrambe le colonne) a un layout `flex-row` (lg) in cui le colonne occupano l'altezza disponibile.
- Colonna sinistra (`lg:w-2/3`) e colonna destra (`lg:w-1/3`) gestite separatamente; la destra resa sticky così la sezione Steps resta in vista.
- **Rimosso** completamente il box "Preview .feature" (l'intero `<div>` con `t.editor.preview` e `{content || t.editor.previewPlaceholder}`). Verificato con grep prima della rimozione che le chiavi i18n fossero usate SOLO in questo box → lasciate intatte in `i18n.ts`.
- Non toccati: FileSidebar (sidebar sinistra), header, tab bar.

### Task 2 — StepBrowser compatto di default (`0ce8608`)
File: `web-ui/src/components/StepBrowser.tsx`

- Aggiunto stato `expandedList` (default `false`).
- Lista risultati con `maxHeight` dinamico: **180px** in stato compatto (default), **480px** quando espansa.
- Pulsante toggle sotto la lista: "Mostra tutti (N) ▼" / "Riduci ▲".
- Ricerca (`Input`) e filtri (pills area/keyword) restano SEMPRE visibili sopra la lista quando il pannello è aperto — non nascosti in modalità compatta.
- Mantenuti: collapse globale `open` (click header), navigazione tastiera (ArrowUp/Down/Enter), param picker.
- Strategia documentata: maxHeight ridotto invece di slice+show-more.

### Task 3 — Verifica visiva (checkpoint human-verify) — APPROVATA
- Verifica visiva del layout editor approvata dall'utente.
- **Rifinitura post-checkpoint** (`3ae4ad0`): su richiesta utente, il comportamento di scroll è stato modificato rispetto al Task 1:
  - Contenitore esterno tornato a `overflow-y-auto` → lo **scroll avviene a livello pagina**.
  - Colonna sinistra (editor scenari): **scorre con la pagina**, nessuno scroll/sticky proprio (rimossi `overflow-y-auto min-h-0`).
  - Colonna destra (Steps): **SOLO questa è sticky** → `lg:sticky lg:top-1 lg:self-start lg:max-h-[calc(100vh-6rem)] lg:overflow-y-auto`, così resta in vista mentre l'editor scorre.
  - Risultato netto identico all'obiettivo del piano (Steps sempre visibile), ma con UX di scroll preferita dall'utente (una sola scrollbar a livello pagina invece di scroll annidato nella colonna editor).
