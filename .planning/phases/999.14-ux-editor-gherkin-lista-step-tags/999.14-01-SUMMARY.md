## What Was Built

### Task 1 — page-markers.ts + api/tags/route.ts

`PageMarkerCount` ora include `steps: string[]` come campo aggiuntivo (campo esistenti `page`, `display`, `stepCount` invariati — backward-compatible).

In `extractPageMarkers`: la Map interna usa `stepsSet: Set<string>` per accumulare i testi step (`sm[2].trim()`) per pagina nel file corrente. Il Set garantisce la deduplicazione intra-file. Alla fine viene materializzato in `steps: [...v.stepsSet]`.

In `TagAggregate` (`route.ts`): aggiunto `steps: string[]`. L'aggregazione itera `steps` di ogni marker e usa `includes()` per deduplicare cross-file. Prima di serializzare, ogni `entry.steps.sort()` ordina alfabeticamente. `stepCount` resta la somma (occorrenze totali, può superare `steps.length` se uno step si ripete tra file).

### Task 2 — tags/page.tsx + i18n.ts

`TagAggregate` locale in `page.tsx` aggiunge `steps: string[]`. Stato `expandedPages: Set<string>` traccia quali slug sono espansi (default: tutti collassati). Funzione `toggleSteps(page)` crea una nuova istanza del Set per garantire re-render React.

Per ogni card: se `steps.length > 0`, appare un pulsante "Mostra step ▼ / Nascondi step ▲" (testo da i18n). Quando aperto, lista step in `font-mono text-xs` con `hover:bg-muted` — stile coerente con StepBrowser.

`i18n.ts`: chiavi `showSteps`, `hideSteps`, `stepsLabel` aggiunte in `en` e `it`.
