Crea `scripts/import-scenarios.ts` completo con le seguenti responsabilità:

**1. Parsing CLI args (process.argv)**
Accetta:
- `--input <path>` (obbligatorio) — file .txt o .feature da importare
- `--app <app>` (opzionale, default: "app-a") — nome app per il path degli step skeleton
- `--area <area>` (opzionale) — se omesso, deriva dal nome Feature nel file o dal nome del file input

**2. Lettura e parsing del file input**
- Leggi il file con `fs.readFileSync(inputPath, 'utf-8')`
- Estrai il nome Feature: cerca riga che inizia con `Feature:` (case-insensitive, strip whitespace)
  - Se non trovata, usa il basename del file input senza estensione
- Estrai gli scenari: ogni blocco che inizia con `Scenario:` o `Scenario Outline:`
  - Nome scenario: tutto ciò che segue `Scenario:` / `Scenario Outline:` sulla stessa riga
  - Step dello scenario: righe che iniziano con `Given|When|Then|And|But|*` (prefisso, case-sensitive per Gherkin) dopo il titolo scenario fino al prossimo `Scenario:` / fine file
  - Ignora `Examples:` e righe tabella `|...|` (non parte degli step da normalizzare)
  - Mantieni le righe `Examples:` / tabella nel file .feature output verbatim

**3. Normalizzazione step (IMP-03)**
Per ogni step raw (es. "Given I am logged in as \"admin\""):
- Strip keyword iniziale: `Given |When |Then |And |But |\* ` (con spazio dopo)
- Sostituisci valori letterali con placeholder Cucumber Expression:
  - Stringhe tra virgolette doppie: `"..."` → `{string}`
  - Stringhe tra virgolette singole: `'...'` → `{string}`
  - Interi standalone (non parte di parole): `\b\d+\b` → `{int}`
  - Float (es. `3.14`): `\b\d+\.\d+\b` → `{float}`
- Trim whitespace
- Il risultato è la `expressionNormalized`

**4. Deduplicazione contro il catalog (IMP-03)**
- Leggi `step-catalog.json` con `fs.readFileSync('step-catalog.json', 'utf-8')` (path relativo dalla root del progetto — lo script va eseguito dalla root)
- Per ogni `expressionNormalized`, verifica se esiste già un entry con `expression === expressionNormalized` nel catalog
- Match esatto (case-sensitive) — non fuzzy
- Separa in due liste: `newSteps` (non presenti), `skippedSteps` (già nel catalog)

**5. Produzione file .feature (IMP-02)**
- Determina `area`: `--area` CLI arg > nome Feature slugified (lowercase, spazi → trattini) > basename file input
- Path output: `src/features/<area>/<slugified-feature-name>.feature`
- Crea le directory intermedie con `fs.mkdirSync(dir, { recursive: true })`
- Contenuto: riscrive il file input come Gherkin valido:
  ```
  @<area>
  Feature: <nome Feature>

    Scenario: <nome scenario>
      Given ...
      When ...
      Then ...
  ```
- Indentazione: 2 spazi per Scenario, 4 spazi per step, 6 spazi per Examples/tabelle
- Se il file .feature esiste già: **non sovrascrivere**, stampa warning e continua

**6. Produzione skeleton step @wanted (IMP-04)**
Per ogni step in `newSteps` (non nel catalog):
- Determina il keyword Cucumber corretto:
  - Step originale iniziava con `Given` → usa `Given`
  - Step originale iniziava con `When` → usa `When`
  - Step originale iniziava con `Then` → usa `Then`
  - Step originale iniziava con `And|But|*` → usa il keyword dell'ultimo step Given/When/Then precedente nello stesso scenario (fallback: `When`)
- Path output skeleton: `src/steps/<app>/imported/<slugified-area>.steps.ts`
  - `<app>` = valore `--app` (default: `app-a`)
  - Se più step hanno la stessa area, tutti finiscono nello stesso file
- Crea le directory con `fs.mkdirSync(dir, { recursive: true })`
- Header file (solo se file nuovo):
  ```typescript
  // src/steps/<app>/imported/<slugified-area>.steps.ts
  // Step skeleton importati da: <inputPath>
  // Generati il: <ISO date>
  // ATTENZIONE: implementazioni da completare manualmente.

  import { Given, When, Then } from "@cucumber/cucumber";
  import { CustomWorld } from "../../../support/world";
  ```
  NOTA: il path relativo `"../../../support/world"` è corretto per `src/steps/<app>/imported/`.
  Se `<app>` è un livello extra, regola il numero di `../` di conseguenza (dalla root `src/steps/`
  sono sempre 3 livelli su: `imported/` → `<app>/` → `steps/` → `src/`, poi `support/world`).
- Per ogni step nel file, aggiungi (senza duplicati nel file stesso):
  ```typescript

  /**
   * @intent    <da completare>
   * @wanted
   * @requester TBD
   */
  <Keyword>(
    "<expressionNormalized>",
    async function (this: CustomWorld) {
      throw new Error('NOT IMPLEMENTED');
    }
  );
  ```
- Se il file skeleton esiste già (import precedente): **append** dei nuovi step, non sovrascrivere. Prima di appendere, leggi il file e skip step la cui expression è già presente nel file (grep sulla stringa).

**7. Chiamata npm run catalog (IMP-05)**
- Dopo aver scritto tutti i file, chiama:
  ```typescript
  import { execSync } from 'child_process';
  execSync('npm run catalog', { stdio: 'inherit' });
  ```
- Se il comando fallisce (es. nessun .feature con step implementati), cattura l'eccezione e stampa un warning chiaro: "catalog rigenerato con warning — verifica manualmente."

**8. Riepilogo finale**
Stampa a console:
```
Import completato.
  Feature file:    src/features/<area>/<name>.feature
  Skeleton steps:  src/steps/<app>/imported/<area>.steps.ts  (<N> step nuovi)
  Step skippati:   <M> già nel catalog
  Catalog:         rigenerato (npm run catalog)
```

**Struttura del file** (top-level, stesso pattern di extract-steps.ts):
- Imports fs, path, child_process
- Helper `slugify(s: string): string` (lowercase + replace /[^a-z0-9]+/g → '-')
- Helper `normalizeStep(rawStep: string): { expression: string, keyword: string }`
- Helper `parseScenarios(content: string): Scenario[]` (interfaccia interna)
- Funzione `main()` che orchestra tutto
- Chiamata `main()` in fondo

**NON fare:**
- NON generare body Playwright (solo `throw new Error('NOT IMPLEMENTED')`)
- NON modificare step-catalog.json direttamente (ci pensa `npm run catalog`)
- NON dipendere da `@cucumber/gherkin` — regex custom come da constraint
- NON usare librerie non già in package.json
