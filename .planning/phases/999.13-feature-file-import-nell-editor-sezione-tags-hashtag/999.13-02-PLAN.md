<objective>
Quando il QA carica un `.feature` nell'editor (Plan 01), proporre **opzionalmente** al catalogo gli step non ancora presenti, ciascuno con il suo marker `# #PAGINA`, tramite un dialog di conferma.

Purpose: il riuso deterministico degli step è il core value del progetto. Caricare un `.feature` da un collega è il momento ideale per arricchire il catalogo: gli step nuovi vanno proposti (status `proposed` sul branch `catalog`), con la pagina di provenienza. Il flusso DEVE essere opzionale (dialog ignorabile) per non forzare proposte indesiderate.

Output: `openContentInNewTab` (Plan 01), dopo aver aperto il tab, se rileva step fuori catalogo apre il pannello proposta esistente con la selezione pre-popolata. Il QA conferma → `doPropose` (flusso esistente, già invia `page`); oppure ignora.

NOTA infrastruttura: `unknownSteps` useMemo e `doPropose` esistono GIÀ e gestiscono GIÀ il campo `page` (estratto da `# #PAGINA`) e l'invio a `/api/catalog/propose` (che già accetta `page`). Questo piano NON reimplementa l'estrazione: la riusa, agganciandola al momento dell'upload.
</objective>

```typescript
useEffect(() => {
  if (!justLoadedTabId || activeTabId !== justLoadedTabId) return;
  // unknownSteps ora riflette il contenuto del tab appena caricato
  if (unknownSteps.length > 0) {
    setProposalSelected(new Set(unknownSteps.map(s => s.expression)));
```
