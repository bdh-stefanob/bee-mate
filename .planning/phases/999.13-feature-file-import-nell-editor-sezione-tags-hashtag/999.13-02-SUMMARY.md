## What Was Built

### Task 1 — _content.tsx

Tre modifiche a `_content.tsx` per gestire il timing asincrono di React:

**1. Nuovo state flag** (riga 145):
```typescript
const [justLoadedTabId, setJustLoadedTabId] = useState<string | null>(null);
```

**2. Assegnazione in `openContentInNewTab`** (dopo `setActiveTabId`):
```typescript
setJustLoadedTabId(tab.id);
```

**3. Nuovo `useEffect` posizionato dopo `unknownSteps` useMemo**:
```typescript
useEffect(() => {
  if (!justLoadedTabId || activeTabId !== justLoadedTabId) return;
  if (unknownSteps.length > 0) {
    setProposalSelected(new Set(unknownSteps.map(s => s.expression)));
    setProposalOpen(true);
  }
  setJustLoadedTabId(null);
}, [justLoadedTabId, unknownSteps, activeTabId]);
```

**Rationale timing:** L'effect di reset su `[activeTabId]` (riga 186) gira al cambio tab e azzera il pannello. Il nuovo effect gira quando `unknownSteps` e' gia' ricalcolato sul nuovo content (dopo che React ha processato il nuovo `activeTabId` e rieseguito il memo), e riapre il pannello solo per il tab appena caricato. Il flag consumato garantisce che il pannello non si riapra mentre il QA modifica il file.

**Flusso opzionale preservato:** Il pannello proposta esistente ha gia' i pulsanti "Ignora" / "Chiudi" — nessuna modifica al JSX o a `doPropose`.

- **Issue:** `unknownSteps` e' un `const` dichiarato con `useMemo` a riga 220. Posizionare il `useEffect` prima della sua dichiarazione causava `TS2448: Block-scoped variable 'unknownSteps' used before its declaration`.
