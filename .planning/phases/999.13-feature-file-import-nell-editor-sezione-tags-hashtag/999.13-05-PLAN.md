Props:
```typescript
interface FeatureImportDialogProps {
  open: boolean;
  fileName: string;          // nome file originale (es. "login.feature")
  content: string;           // contenuto verbatim del file caricato
  existingApps: string[];    // valori app esistenti (per datalist)
  existingFlows: string[];   // valori flow esistenti (per datalist)
  existingPaths: string[];   // file path esistenti (per guardia anti-overwrite)
  onCancel: () => void;
  onSaved: (savedPath: string) => void;
}
```

Comportamento:
1. All'apertura, calcola i suggerimenti:
   - `tags` dal contenuto (regex sopra) → `suggestedApp = slugify(tags[0] ?? '')`, `suggestedFlow = slugify(tags[1] ?? '')`.
   - se `suggestedFlow` è vuoto, usa `slugify(extractPageMarkers(content)[0]?.page ?? '')` come fallback flow.
   - `detectedPages = extractPageMarkers(content).map(p => p.display)` per il riepilogo "Pagine rilevate".
   - inizializza lo stato `app` e `flow` con i suggerimenti (campi editabili).
2. Render: due `<input list=...>` con `<datalist>` popolati da `existingApps` / `existingFlows`; sezione "Pagine rilevate: …"; anteprima del path di destinazione `src/features/{slugify(app)}/{slugify(flow)}/{baseName}.feature` (baseName = fileName senza directory, mantieni l'estensione .feature).
3. Guardia anti-overwrite: calcola `targetRel = {appSlug}/{flowSlug}/{baseName}.feature`. Se `existingPaths` contiene un path che corrisponde (confronta in modo robusto: gli `existingPaths` possono essere relativi a src/features o includere prefissi — normalizza confrontando la coda `{app}/{flow}/{file}`), mostra un avviso giallo "Esiste già un file in questo percorso — sovrascrivere?" e disabilita "Salva" finché l'utente non spunta una checkbox di conferma.
4. Salvataggio: `POST /api/features` con `{ content, filePath: targetRel }` (content VERBATIM, non modificato). Su ok → `onSaved(data.path)`. Gestisci stato loading/errore con toast (sonner, come nel resto dell'app).
5. Validazione: "Salva" disabilitato se `app` o `flow` (slugificati) sono vuoti.
