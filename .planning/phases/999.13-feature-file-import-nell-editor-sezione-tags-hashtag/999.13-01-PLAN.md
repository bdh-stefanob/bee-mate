<objective>
Permettere al QA di caricare un file `.feature` direttamente nell'editor (drag-and-drop o file picker già presenti in `ImportDropzone`) aprendolo in un **nuovo tab**, preservando tutti i commenti (`# #PAGINA`, `# note libere`), senza passare dalla pagina Features.

Purpose: oggi `ImportDropzone.onImported` chiama `setContent` che **sovrascrive** il tab attivo, e i file `.feature` reali finiscono erroneamente in `/api/import` (lo script `import-scenarios.ts`, pensato per i `.txt` del formato esteso QA). Questo distrugge il workflow: il QA perde il lavoro nel tab corrente e i commenti possono essere riscritti dal parser.

Output: `ImportDropzone` distingue tre casi (`.feature` verbatim → nuovo tab; `.txt`/extended → comportamento esistente nel tab corrente); l'editor apre il `.feature` in un tab dedicato con label derivata da `Feature:`.
</objective>
