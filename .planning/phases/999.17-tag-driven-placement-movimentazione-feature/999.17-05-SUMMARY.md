# Phase 999.17 Plan 05: Save unificato (nome stabile, move, anti-overwrite) Summary

Save dell'editor reso intuitivo e privo di bug: nome file stabile (identità del file aperto), cambio tag → spostamento via `/api/features/move` con contenuto corrente, file nuovo con collisione → conferma overwrite. Niente più duplicati né sovrascritture silenziose.

## What Was Built

### Task 1 — move accetta content opzionale (`e12d947`)
- Esteso il body di `POST /api/features/move` con un campo opzionale `content?: string`.
- Se `content` è presente (e non vuoto) → usa quel testo come base, applica comunque `setFeatureTags(content, appSlug, flowSlug)` e lo scrive in `dest`, senza leggere il file sorgente per il body.
- Se `content` è assente → comportamento invariato (legge il contenuto dal disco).
- Anti-overwrite 409, rimozione sorgente, cleanup cartelle vuote e ritorno `{ ok, path }` invariati.
- Backward-compatible: la pagina /features (bottone "Sposta" + drag&drop) continua a chiamare senza `content`.

### Task 2 — handleSave unificato (`84dad88`)
- Helper `basenameOf(p)`: ultimo segmento del path POSIX (nome file stabile).
- `handleSave` riscritto:
  - `baseName` = basename del file aperto se esiste (`activeTab.filePath`), altrimenti `${titleSlug}.feature` per i file nuovi.
  - Tag mancanti → dialog placement (azione 'save').
  - File esistente, `targetPath === existingPath` → salva **in-place**.
  - File esistente, `targetPath !== existingPath` → **SPOSTA** via `/api/features/move` con `content` corrente; 409 → toast, no overwrite; ok → aggiorna `tab.filePath`, `dirty:false`, label.
  - File nuovo con collisione su `existingPaths` (match su coda normalizzata) → dialog placement (conferma overwrite); altrimenti `doSaveContent`.
- Ramo `onConfirm` del placement dialog allineato: usa lo stesso `stableBaseName` e la stessa scelta in-place/sposta/nuovo, dopo aver scritto i tag nel contenuto.
- `loadFeatureList()` chiamato all'inizio di `handleSave` (cache via ref → costo solo al primo save) per garantire `existingPaths`.
- Ctrl+S resta funzionante con la nuova logica.
