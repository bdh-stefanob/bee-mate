# Phase 999.17 Plan 02: Save tag-driven con FeaturePlacementDialog Summary

Save tag-driven nell'editor: dialog placement se @app/@flow mancano, salvataggio diretto se i tag sono completi; bottone "Cartella" per impostare i tag on-demand.

## What Was Built

Il salvataggio dall'editor (`handleSave`) ora usa `getFeatureTags` per decidere il comportamento:

- **Tag completi** (`@app @flow` presenti): il file viene salvato direttamente in `{app}/{flow}/{slug}.feature` — Ctrl+S rimane veloce, nessun modale.
- **Tag mancanti** (uno o entrambi assenti): si apre `FeaturePlacementDialog`; all'`onConfirm`, `setFeatureTags` scrive i tag nel contenuto, poi `doSaveContent` esegue il POST verso il percorso corretto.

Un bottone "Cartella" nell'header apre il dialog on-demand (utile subito dopo "+"): all'`onConfirm` applica i tag al contenuto senza salvare; l'utente poi preme Save.

Il dialog è alimentato da `GET /api/features` (caricato lazy al primo open) per `existingApps`, `existingFlows` e `existingPaths` (autocomplete + anti-overwrite).
