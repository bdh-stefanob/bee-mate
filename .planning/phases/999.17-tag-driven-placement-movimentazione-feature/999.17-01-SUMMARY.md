## What Was Built

### `web-ui/src/lib/feature-tags.ts`

- `getFeatureTags(content)` — legge `@app` e `@flow` dalla prima riga tag nel contenuto; restituisce `{ app: string|null, flow: string|null }`
- `setFeatureTags(content, app, flow)` — sostituisce la riga tag esistente (prima riga non vuota che inizia con `@`) o la inserisce prima di `Feature:` (o in cima se non presente); preserva il resto del contenuto verbatim

### `web-ui/src/components/FeaturePlacementDialog.tsx`

Dialog generico `'use client'` per la scelta collocazione di un feature file:
- Props: `open`, `title`, `fileBaseName`, `suggestedApp?`, `suggestedFlow?`, `detectedPages?`, `existingApps`, `existingFlows`, `existingPaths`, `confirmLabel?`, `onCancel`, `onConfirm(app, flow, targetRel)`
- Funzionalità: input App/Flow con `<datalist>` autocomplete, anteprima path `src/features/{app}/{flow}/{file}`, guardia anti-overwrite con checkbox conferma, pulsante Conferma disabilitato se app/flow vuoti
- **Nessun fetch interno**: l'azione (save/move/altro) è delegata al chiamante via `onConfirm`

### `web-ui/src/components/FeatureImportDialog.tsx` (refactored)

- Firma esterna **invariata**: `{ open, fileName, content, existingApps, existingFlows, existingPaths, onCancel, onSaved }` — `features/page.tsx` non richiede modifiche
- Internamente delega la UI a `FeaturePlacementDialog`
- Usa `getFeatureTags` per derivare `suggestedApp`/`suggestedFlow` dai tag + fallback `extractPageMarkers`
- `onConfirm` esegue il POST `/api/features` con il content verbatim e chiama `onSaved`

---

## Decisions Made

1. **FeaturePlacementDialog senza fetch**: il dialog è puramente UI — decide solo app/flow/targetRel e notifica il chiamante. Questo consente riuso identico per import, save e move (piani 02/03/04) senza logica condizionale nel dialog.
2. **slugify locale nel dialog**: evita import di `@/lib/repo` (che importa `path` e potrebbe causare problemi in contesti client) e mantiene il componente autonomo.
3. **Firma FeatureImportDialog invariata**: retrocompatibilità completa con il codice esistente; nessuna modifica propagata a `features/page.tsx`.
4. **`getFeatureTags` come wrapper tipizzato**: formalizza il pattern regex già usato in `_content.tsx` in un helper con tipo di ritorno esplicito, preparando il terreno per i piani successivi.
