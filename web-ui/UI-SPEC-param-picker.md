## Data Model Additions

### Extended `CatalogStep` interface

```typescript
// web-ui/src/lib/types.ts — additions to existing CatalogStep

interface ParamEnumDef {
  /** The param token as it appears in the expression, e.g. "{string}" */
  token: string;
  /** Known valid values. Empty array means free-text only. */
  values: string[];
  /** Optional display label for the field, e.g. "Navigation item" */
  label?: string;
}

interface CatalogStep {
  expression: string;
  parameters: string[];           // existing — e.g. ["{string}"]
  app: string;
  area: string;
  domain: string;
  status: 'implemented' | 'wanted' | 'deprecated';
  page?: string;
  requester?: string;
  sourceRef: string;
  documented: boolean;
  // NEW:
  paramEnums?: ParamEnumDef[];    // one entry per param token that has known values
  requires?: string[];            // prerequisite step expressions (exact match)
}
```

### Where enum values live: `step-enums.json` (separate file)

**Decision: separate `step-enums.json`, manually managed by editors.**

Rationale:
- `step-catalog.json` is machine-generated by `npm run catalog` and would be overwritten on every run. Writing enum values into it would be lost.
- Enum values are curated editorial content, not extracted from code. They belong in a hand-managed file.
- The API route at `/api/catalog` merges both files at request time — zero build step required.

```jsonc
// step-enums.json (repo root, next to step-catalog.json)
{
  "version": 1,
  "enums": [
    {
      "expression": "the user clicks on {string}",
      "paramEnums": [
        {
          "token": "{string}",
          "label": "Navigation item",
          "values": ["I'm new", "Weight loss", "Pharmacy", "Repeat prescription"]
        }
      ]
    }
  ],
  "dependencies": [
    {
      "expression": "the user adds to basket",
      "requires": ["the user is on the product page"]
    }
  ]
}
```

The merge logic in `/api/catalog/route.ts`:
```typescript
// Pseudocode — merge at request time
const catalog = JSON.parse(fs.readFileSync('step-catalog.json'));
const enums   = fs.existsSync('step-enums.json')
  ? JSON.parse(fs.readFileSync('step-enums.json'))
  : { enums: [], dependencies: [] };

const enumMap = new Map(enums.enums.map(e => [e.expression, e]));
const depsMap = new Map(enums.dependencies.map(d => [d.expression, d.requires]));

catalog.steps = catalog.steps.map(step => ({
  ...step,
  paramEnums: enumMap.get(step.expression)?.paramEnums ?? [],
  requires:   depsMap.get(step.expression) ?? [],
}));
```

## Feature 1: Parametric Step Picker

### 1a. Visual indicator on step list rows

A step row in StepBrowser has three states:

| State | Indicator |
|-------|-----------|
| No parameters | No indicator |
| Has params, no enum values | Small grey `{P}` badge — `text-[10px] text-muted-foreground` |
| Has params with enum values | Small teal chip using `--primary` color: `text-[10px] text-primary-foreground bg-primary/10 border border-primary/20` + filled circle icon (`CircleDot`, size 10px) |
| Has dependency hint | Small orange dot on left edge of row (see Feature 2) |

**Rule:** The param chip appears at the far right of the row, after the status badge. It never wraps — the row stays 32px tall.

ASCII mockup — step list row variants:

```
WITHOUT PARAMS (32px row):
+-----------------------------------------------------------------------+
| Given the user is on the homepage               [implemented]         |
+-----------------------------------------------------------------------+

WITH PARAMS + ENUM (32px row):
+-----------------------------------------------------------------------+
| When the user clicks on {string}                [implemented] [* ~]  |
+-----------------------------------------------------------------------+
  (* = filled dot icon, ~ = "2 values" label, teal chip)

WITH PARAMS + FREE TEXT ONLY (32px row):
+-----------------------------------------------------------------------+
| When the user types {string} in the field       [implemented] [{P}]  |
+-----------------------------------------------------------------------+
  ({P} = grey badge, no enum list available)

WITH DEPENDENCY HINT (orange dot on left edge):
+-----------------------------------------------------------------------+
| • When the user adds to basket                  [implemented] [* ~]  |
+-----------------------------------------------------------------------+
  (• = 6px orange dot, left-aligned, meaning "has prerequisites")
```

**Concrete Tailwind classes for the free-text badge:**

### 1b. Click behavior

| Condition | On Click |
|-----------|----------|
| Step has no parameters | Insert immediately (existing behavior) |
| Step has parameters, all free-text | Open StepParamPicker popover |
| Step has parameters, at least one has enum values | Open StepParamPicker popover |

No double-click required — single click triggers either immediate insert or picker open.

### 1c. Interaction flow

1. User sees StepBrowser panel on the right. Steps are listed compactly.
2. User clicks a step row that has enum params (e.g. "When the user clicks on {string}").
3. StepParamPicker popover opens, anchored to the clicked row (side="left", sideOffset=8). If the row is in the bottom third of the viewport, the popover opens upward (side="top").
4. The picker header shows the step keyword (Given/When/Then/And) and the step expression with `{param}` tokens highlighted in orange.
5. For each `{param}` token in the expression, one field is rendered:
   - If `paramEnums` has values for this token: a `Select` dropdown pre-populated with the enum values, showing a placeholder "Select {label}...".
   - If no enum values: a text `Input` with placeholder `Enter value...`.
6. Below the fields, a live **Preview line** shows the resolved step as it will be inserted. Unresolved params are shown as `{string}` in muted orange.
7. User fills all fields (Tab through them). Enter on the last field triggers Confirm.
8. User presses "Insert" button (or Enter on last field). The picker closes and the resolved step is inserted into the editor at the current cursor position.
9. The inserted text format: `    {Keyword} {resolved expression}\n` — 4-space indent, single trailing newline. String values are wrapped in single quotes: `'I'm new'`.
10. Escape at any point closes the picker without inserting.

### 1d. StepParamPicker component

**File:** `web-ui/src/components/StepParamPicker.tsx`

**Props:**
```typescript
interface StepParamPickerProps {
  step: CatalogStep;
  keyword: 'Given' | 'When' | 'Then' | 'And' | 'But';
  anchorRef: React.RefObject<HTMLElement>;
  open: boolean;
  onInsert: (resolvedLine: string) => void;
  onClose: () => void;
}
```

**Internal state:**
```typescript
// Map from token (e.g. "{string}") to current value string
const [values, setValues] = useState<Record<string, string>>({});
```

**Resolved expression logic:**
```typescript
function resolveExpression(expression: string, values: Record<string, string>): string {
  // Replace each {token} with its value, or keep as-is if empty
  return expression.replace(/\{[^}]+\}/g, (match) => {
    const val = values[match];
    return val ? `'${val}'` : match;
  });
}

function buildInsertLine(keyword: string, resolved: string): string {
  return `    ${keyword} ${resolved}`;
}
```

**Implementation note:** Use the shadcn `Popover` component (`@base-ui/react` based, matching the existing Select component pattern). Do NOT use Dialog — the picker is a lightweight inline popover, not a full modal overlay.

**"Insert step" button state:**
- Enabled only when ALL param fields have non-empty values.

## Feature 2: Dependency Hint

### 2a. Interaction flow

1. Step has `requires: string[]` with at least one expression.
2. In the step list row, a 6px filled orange dot appears on the left edge of the row (not the status badge area, specifically left-edge of the row container).
3. User hovers the dot OR the step row. After 400ms hover delay, a tooltip opens.
4. Tooltip shows:
   - Header: "Requires:" in 11px/medium
   - Each prerequisite expression as a bullet, 12px/400
5. No click interaction. Tooltip closes on mouse-leave or focus-leave.
6. If `requires` is empty → no dot, no tooltip.

### 2b. Dependency indicator component

**Implementation:** Use the shadcn `Tooltip` component (`TooltipProvider`, `Tooltip`, `TooltipTrigger`, `TooltipContent`).

**Install command:** `npx shadcn@latest add tooltip`

**The orange dot:** A `<span>` with `className="absolute left-0 top-1/2 -translate-y-1/2 size-1.5 rounded-full bg-accent"` inside the row's `relative` container.

**Tooltip content layout:**
```
+----[ Tooltip, max-width 280px ]-----------+
| Requires:                                  |
| • the user is on the product page          |
| • the user has added a product to basket   |
+--------------------------------------------+
```

## Keyboard Navigation Spec

### StepBrowser list

| Key | Action |
|-----|--------|
| `ArrowUp` / `ArrowDown` | Move focus between step rows |
| `Enter` | Trigger click behavior of focused row (open picker or insert) |
| `Tab` | Move focus out of list to next focusable element |

Step rows must have `role="listitem"` (parent: `role="list"`). Focusable with `tabIndex={0}`.

### StepParamPicker popover

| Key | Action |
|-----|--------|
| `Tab` | Move focus: keyword buttons → param fields (top to bottom) → Cancel → Insert |
| `Shift+Tab` | Reverse order |
| `Enter` on Insert button | Confirm and insert |
| `Enter` on last param field | If all fields filled, same as clicking Insert |
| `Escape` | Close picker, return focus to triggering step row |
| `Space` / `Enter` on keyword button | Select that keyword |

**Focus management:**
- When picker opens, focus goes to the first param field (skipping keyword buttons unless user tabs back).
- When picker closes via Escape or Cancel, focus returns to the step row that triggered it (`anchorRef`).
- The popover must trap focus while open — use `@base-ui/react/dialog` focus trap if needed, or implement manually with `useEffect` + `focusTrap`.

### Dependency tooltip

| Key | Action |
|-----|--------|
| `Tab` into step row with dependency | Tooltip does NOT auto-open on focus (keyboard users see the dot; tooltip is hover-only) |
| `F2` on focused step row | Open tooltip (supplementary keyboard access for dependency hint) — optional enhancement |

Note: `F2` for tooltip access is a progressive enhancement only. The dependency hint is informational; screen readers will announce it via `aria-describedby` instead.

**ARIA additions for dependency hint:**
```tsx
// On the step row element:
aria-describedby={step.requires?.length ? `dep-hint-${stepId}` : undefined}

// Hidden element (screen reader only):
<span id={`dep-hint-${stepId}`} className="sr-only">
  Requires: {step.requires.join(', ')}
</span>
```

## Edge Cases

### E1 — Step has parameters but no enum values for any token

Picker opens normally. All param fields render as `<Input>` (free-text). "Insert step" button is enabled only when all inputs are non-empty. No dropdown, no enum chip in the list row — only the `{P}` grey badge.

### E2 — Step has multiple parameters, some with enums, some free-text

Each parameter field is rendered independently. Enum params get `Select`, free-text params get `Input`. Both must be filled for Insert to enable. The preview line updates in real-time as each field changes.

### E3 — Enum list is very long (>10 values)

The `Select` component (base-ui based, already in codebase) supports `ScrollUpArrow` and `ScrollDownArrow` — use them. The popup has `max-h-(--available-height)` already set in `SelectContent`. No additional handling needed. If >20 values, add a `Combobox` (searchable select) instead of plain Select — see E3b.

### E3b — Enum list > 20 values: use Combobox

If `paramEnums[token].values.length > 20`, render a `Combobox` pattern: an `Input` with a filterable dropdown. Implementation: local filter state + `SelectContent` rendered below the input. Install: `npx shadcn@latest add combobox`. Threshold is 20 — hardcoded constant `ENUM_COMBOBOX_THRESHOLD = 20` in `StepParamPicker.tsx`.

### E4 — Expression has no `{param}` tokens but `parameters` array is non-empty

This is a data inconsistency. The picker should not open for such a step. Guard: check `expression.match(/\{[^}]+\}/g)` before triggering picker. If mismatch detected, fall back to immediate insert and log `console.warn`.

### E5 — Picker anchor row scrolls out of view while picker is open

The popover is anchored via `anchorRef`. If the user scrolls the StepBrowser list, the anchor moves. Base-ui Popover uses portal rendering + position recalculation. No special handling needed — the popover repositions automatically. If the anchor scrolls entirely out of the scrollport, close the picker (`IntersectionObserver` on the anchor element, threshold 0).

### E6 — Step expression string value contains a single quote

Example: value `"I'm new"` already contains `'`. The insert logic must escape it:

```typescript
function escapeGherkinString(val: string): string {
  // Gherkin string params use double quotes: "value"
  // Use double quotes if value contains single quote
  const hasSingle = val.includes("'");
  if (hasSingle) return `"${val.replace(/"/g, '\\"')}"`;
  return `'${val}'`;
}
```

Insert result: `    When the user clicks on "I'm new"`.

### E7 — Dependency: required step not in the current catalog

The `requires` array stores expression strings. If a referenced expression no longer exists in the catalog (e.g., it was renamed), the tooltip still shows it as-is. No red/broken indicator needed for this phase. This is a data quality issue for `step-enums.json` editors to manage.

### E8 — StepBrowser is very narrow (< 280px, e.g. resized panel)

The param chip clips at `max-w-[60px] truncate`. The status badge remains visible at all times (it is rendered first, before the chip). The picker popover has a fixed `width-[320px]` and uses portal rendering — it escapes the narrow panel.

## Implementation Notes for Executor

1. **Popover vs Dialog:** Use `Popover` (not `Dialog`). The picker is anchored to a row, not a page-level action. Dialog adds an overlay and blocks page interaction — not desired here.

2. **Base-ui Popover import pattern:** The existing `select.tsx` uses `@base-ui/react/select`. The Tooltip and Popover follow the same pattern. Check `web-ui/node_modules/@base-ui/react/` for available packages before installing additional dependencies.

3. **Keyword detection from editor:** The `GherkinEditor` component should expose the last-used keyword via a callback or via shared state (e.g., a Zustand atom or React context). For the demo, a simple `useState` passed down from the page layout is sufficient. If the editor exposes no keyword, StepBrowser defaults to "Given".

4. **Single-quote escaping in Gherkin:** The canonical quoting style for step parameters in this codebase is single quotes (visible in existing `.feature` files). See E6 for the escape rule when the value itself contains a single quote.

5. **`step-enums.json` path:** Same directory as `step-catalog.json`, i.e., `REPO_ROOT/step-enums.json`. The `/api/catalog` merge reads it with `fs.existsSync` guard — the app starts correctly even if the file does not exist yet.

6. **Accessibility — picker focus trap:** The Popover component from base-ui does NOT automatically trap focus. Add a manual focus trap: when `open` becomes true, use `useEffect` to find all focusable children and intercept Tab/Shift+Tab to cycle within. Return focus to `anchorRef.current` on close.

7. **Dark mode:** All color tokens used (`bg-primary/10`, `text-primary`, `bg-accent`, `text-muted-foreground`) resolve correctly in both light and dark mode via CSS variables declared in `globals.css`. No hardcoded OKLCH values in component code.
